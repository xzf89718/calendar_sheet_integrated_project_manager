# weekreport_clean —— 周报清洗

清洗**周报模式导出的周报 xlsx**，去掉不属于"当周真实跟进"的行。
GUI / CLI 双入口，功能一一对应（v3.6.1 起 CLI 化，启动接口与
workbench_ui 统一：`python -m weekreport_clean gui`）。

## 要解决什么问题

周报的取数口径是"写入时间落在本周"的快照。但这个口径会被两种
操作污染：

- **大规模导入**——批量导入历史数据时，大量旧跟进记录的写入时间
  落在本周，全部涌进周报；
- **修改过去的跟进记录**——补录、改错历史快照，写入时间是今天，
  记录的却是过去某天的事。

这些行写进周报会歪曲"本周做了什么"，但逐行手删又费时且易错。

## 清洗原理：同一天匹配

对每一行取**第一列（写入时间）**，与**「跟进记录」列的文本**做
日期匹配：

- 跟进记录里出现**同一天**（完整日期，写法不限："2026年10月20日"、
  "2026/10/20"、"2026-10-20" 都认，按年月日三元组比对）→ **保留**
  ——写入时间和跟进内容是同一天，是真实的当日跟进；
- 否则 → **丢弃**——写入行为（导入/补录）与跟进不是同一天，
  正是要规避的行。

注意：跟进记录里必须写**含年份的完整日期**才参与匹配；只写
"11月3日" 这类不带年份的日期无法判定，该行会被丢弃。

纯函数实现（`clean_core.py`），不依赖 GUI/CLI；只处理 xlsx 文件，
不碰数据库。

## 运行

```bash
python -m weekreport_clean gui                        # 图形界面
python -m weekreport_clean preview <file.xlsx>        # 预览（只读）
python -m weekreport_clean clean <file.xlsx> [-o out.xlsx]   # 生成清洗结果
```

`setup.ps1` / `setup.sh` 之后可直接敲 `weekreport_clean ...`。

## 命令

| 命令 | 说明 |
|------|------|
| `gui` | 图形界面（原 clean_gui.py 入口不变，也保留） |
| `preview <file>` | 终端逐行打印 [保留]/[丢弃] + 汇总；不写任何文件 |
| `clean <file> [-o out]` | 写出清洗结果 xlsx；不带 `-o` 默认 `<原名>_cleaned.xlsx`（同目录，已存在覆盖；显式 `-o` 的父目录自动创建） |

退出码：0 成功；1 业务错误（stderr，无 traceback）；2 参数错误。

## CLI 与 GUI 的对应

| GUI 操作 | CLI 等价 |
|----------|----------|
| 浏览 + 加载文件 | `preview` / `clean` 的位置参数 |
| 上表"原始内容" | `preview` 的全部行（[保留]/[丢弃] 标记） |
| 「清洗预览」+ 下表"清洗结果" | `preview` 的保留行 / `clean` 的输出文件 |
| 「导出清洗结果」 | `clean`（结果为空时拒绝写出，两入口一致） |

## 工作流

1. 主程序周报模式 →「导出周报」得到 xlsx
2. `python -m weekreport_clean preview 周报.xlsx` 核对保留/丢弃
3. `python -m weekreport_clean clean 周报.xlsx` 生成清洗结果
4. 或启动 `gui` 用双表对照、点按钮导出（等价流程）

数据唯一入口仍是主程序的「导入」；本模块只清洗周报文件，
不直接写库。
